配图怎么看

截图来自仓库中真实 HTML、CSS 和交互脚本的浏览器渲染；为便于覆盖功能，状态、SN、版本、读数、文件清单和任务结果使用示例数据。红色圆圈为本手册添加的定位编号，不是页面原有控件。

盖板正常/损坏照片是系统自带的历史实拍样本。它们仅供外观对照，不代表当前设备状态。本文未通过升级、标零或测试录制来制造演示结果。

版本与设备差异

页面显示的传感器数量取决于设备配置。胸部主摄为可选项；不含双目的版本不应按完整双目配置验收。旧安装包可能缺少某些入口或密码弹窗，应以实际部署版本为准。

本手册不包含维护密码。需要执行修改操作时，请向设备管理员获取。密码只是操作门槛，不能替代治具、正确文件、设备检查和操作确认。
开始使用

01 · 连接设备并打开网页

设备上电→网线接电脑→同网段地址→HTTPS 访问

准备条件

  • 设备供电稳定，设备管理 Web 服务已随软件安装。
  • 电脑与设备通过以太网连接；推荐使用近期版本的 Chrome 或 Edge。
  • 若设备使用默认地址，可将电脑有线网口设为一个未占用地址，例如 192.168.2.100，子网掩码 255.255.255.0。直连通常不需要网关。

操作步骤

  1. 在浏览器地址栏输入 https://192.168.2.240:8080/。若管理员更改过设备网口地址，使用实际地址。
  2. 首次访问可能显示自签名证书提示。先核对连接的是自己的设备；按组织要求核对证书后，再选择继续访问。若电脑策略禁止继续，交由管理员处理证书信任。
  3. 进入页面后无需账号登录。等待右上角连接状态更新，并核对页面中的设备 SN。
  4. 点击四个页签切换：“设备概览”“录制数据”“升级维护”“配置”。
必须使用 https，并保留端口 8080。默认只绑定设备以太网地址；连上 Wi-Fi 不代表可以访问这个页面。
通用操作

02 · 语言、确认与维护密码

入口行为与操作方法
Language / 语言右上角选择中文或 English，仅临时切换当前页面显示。刷新后跟随设备保存的语言；日志原文不翻译。
维护密码修改设备参数、编码器标零、上传安装软件、升级固件时，在确认弹窗中输入。密码区分大小写，不能多输空格。
确认执行确认弹窗中操作对象、左右侧和参数后提交。标零还必须勾选已安装指定治具；仅输入密码不能跳过此项。
取消 / Esc关闭确认弹窗，不提交此次操作；已输入的密码清空。任务提交后的关闭网页不等于取消后台任务。

密码错误后怎么办

页面提示“维护密码错误，请重新输入”时，本次受保护请求不会派发维护任务。重新点击原操作按钮，核对操作内容并再次输入；软件升级需重新发起上传。不要把密码放入文件名、截图或发送给无关人员。

密码不会形成“长期解锁”状态。每次受保护的新操作都需输入；上传与随后的执行属于同一次升级。查看状态、下载、抓图、盖板检测及编码器读取仍免密码；触觉基线重置只需弹框确认。
设备概览

03 · 读懂概览与硬件状态

区域是什么意思 / 应如何使用
背包电量显示百分比和充电/放电状态；电量 ≤10% 时突出显示。电量不可用表示未取得有效状态，不等于 0%。
CPU / 内存当前系统负载和已用/总内存。用于观察运行压力；某一瞬间升高不直接证明故障。
数据盘 / 系统盘分别显示剩余空间和容量。“未挂载”时应先检查数据盘，不能当作空盘使用。
左右设备 / SN按物理左右侧查看设备是否识别；标题后的 SN 是夹爪身份。断开或状态不新鲜时可能显示“—”。
已识别 / 正常出流“已识别”表示系统能看到设备节点，不保证通信、图像或固件均正常；“正常出流”还具有流状态证据。
暂未出流 / 未识别分别表示已发现设备但缺少新鲜出流证据，或尚未看到设备。待启动稳定后复查，持续异常再取日志。

状态一般约每 3 秒刷新。“数采服务在线”表示服务运行；“空闲”表示当前未显示录制或维护占用。两者都不等于所有传感器已经完成质量验收。

设备概览 · Ego

04 · Ego 绑定、连接和时间状态

字段含义
绑定状态 / 序列号显示当前绑定关系和目标 Ego 身份。网页只展示绑定结果，没有绑定/解绑按钮；绑定使用设备既有实体操作流程。
连接状态已绑定后查看是否在线。未绑定时显示“未检测（未绑定）”；未知表示证据缺失或过期，不能直接认定已连接。
电量绑定且取得有效电量快照时显示百分比及充电状态；无有效数据时显示不可用。
时间同步显示已与背包同步、同步中、连接断开、授时异常或旧版录制前校时。旧应用可能采用不同同步方式。
与背包偏差 / RTT偏差为报告的时钟差；RTT 为往返通信延迟，单位毫秒。“暂无测量”表示没有有效数据。它们不直接等于视频光学同步误差。
固件 / 软件版本分别对应 Ego 系统固件与应用版本。断连后可显示“缓存”，不表示当前还能正常通信。
USB 存储模式可见不代表 Ego 采集通信正常。若已绑定但断连，先检查电源、USB 和 Ego 应用，再刷新状态；不要仅凭缓存版本认为设备在线。
设备概览 · 相机抓图

05 · 获取本机与 Ego 图片

功能用途和结果
获取本机相机图片按当前采集配置检查主摄、双目、触觉及启用的胸部主摄。双目每侧输出一张双眼拼接图；触觉图片显示在触觉盖板区域。
获取 Ego 图片选择已绑定 Ego，或未绑定时唯一在线 Ego，短录约 3 秒，拉取 RGB / ctrl / tracking 视频并截帧。不是实时视频预览。

操作步骤

  1. 停止正式录制、下载和其他维护；确认页面状态允许操作。
  2. 点击所需按钮，等待“获取完成”。Ego 还需短录、收尾、拉取和截帧，可能比本机更慢。
  3. 逐路查看图像是否清晰、曝光是否合理、视野和左右安装是否正确。
  4. 点击图片可在新标签页查看原图。出现“部分相机获取失败”时查看具体相机下的错误，不要把局部成功当作全部成功。

需要知道的边界

  • 本机抓图是各路分别取帧，不能据此证明相机同时曝光或时间同步合格。
  • Ego 三路取图全部成功后会删除本次创建的远端测试数据；失败或清理失败会保留证据并报告，不应随意删除原有录制。
  • 下一次抓图或检测会清理上次本地预览。要保留图片，应及时通过浏览器保存。
设备概览 · 触觉盖板

06 · 运行盖板损坏检测

  1. 将夹爪张开，确保四块触觉盖板无接触、无遮挡；去除外部物体干扰。
  2. 确认没有录制或维护任务，点击“盖板损坏检测”。无需维护密码。
  3. 等待四路采集和分析，按“左/右夹爪 + 左/右触觉传感器”逐个查看。
  4. 核对 camera key 与传感器 SN，分别查看短期基线和长期基线的本次结论。
本次结果怎么处理
正常本次相对该基线未发现异常；仍需结合实物外观和连续告警。
疑似盖板损坏查看红色 mask 标出的可疑区域，先排除接触和遮挡，再由维护人员检查实物。
基线不匹配图像与基线存在不适合直接比较的差异，应核对传感器、外观及安装；不要直接判定损坏或正常。
尚未建立基线缺少对应比较基准；由维护人员确认盖板完好后建立适当基线。
采集错误 / 未连接本次没有可用判断，先处理连接或采集问题，再重新检测。
设备概览 · 触觉基线维护

07 · 告警标签与基线重置

连续告警与单次检测是两回事

图片标题旁标签反映连续检测历史：黄色为盖板损坏告警，绿色为无损坏告警，灰色为状态未知或未连接。图片下方是本次检测结论。单次检测正常不会直接清除黄灯。设备换成另一 SN 后，旧图片会提示重新取图。

按钮修改范围
重置短期基线使用当前成功采集的图片替换 reference，并清除该基线对应的检测历史与告警。
重置长期基线替换 persistent。长期基线用于保留稳定参考，不应为了消除告警随意覆盖。
重置长短期基线同时替换两个基线。仅在两者均应重建时使用。

正确流程

  1. 先人工确认盖板完好、无接触、无遮挡，且图片确属当前传感器。
  2. 重新检测并检查图片，在采集成功后的 2 分钟内点击需要的重置按钮。
  3. 核对侧别与范围，在弹框中确认盖板完好、无接触且无遮挡后执行；无需输入密码。
  4. 完成后重新运行检测，检查新结果与告警。只重置一类基线时，另一类的告警仍保留。
重置会改变检测依据，不能修复物理损坏。图片过期、SN 改变或采集失败时应重新取图，不能强行使用旧图。
设备概览 · 外观参考

08 · 正常与损坏实拍例图

如何使用“正常与损坏例图”

  1. 在触觉盖板区域展开该项，查看两张历史实拍图片。
  2. 对照可见外观差异，辅助理解损坏可能出现的纹理、斑块或结构变化。
  3. 回到“盖板损坏检测”，以当前设备采集结果和实物检查作为处理依据。
你看到的图应如何理解
历史正常/损坏例图固定参考样本，不随当前设备刷新，不用于判断当前传感器是否合格。
当前图本次采集的触觉图像。先确认没有接触物、遮挡或采集异常。
检测状态图 / mask算法标记疑似异常区域，需结合对应基线、本次状态和实物共同判断。
正常图与损坏图没有覆盖所有真实故障形态。图片相似、颜色接近或绿色标签都不能替代必要的人工核查。

图片来源：Web 自带 tactile-normal.png 与 tactile-damaged.png。损坏样本来源记录见项目 static/tactile-examples.json。

设备概览 · 故障材料

09 · 获取设备日志

用途

下载设备日志包，供技术支持检查数采、相机、USB、维护任务和系统运行情况。日志包不是录制视频，也不是整块数据盘的备份。

操作步骤

  1. 先记录异常出现的时间、设备 SN、当时操作和屏幕提示。
  2. 待设备结束录制、收尾或维护，在设备概览底部点击“获取日志”。
  3. 在浏览器下载列表中等待 ugripper-logs.tar.gz 完成。
  4. 提交日志时附上异常时间、相关 episode 名称和必要截图。保留原始压缩包。
包内内容作用
system.log由维护服务获取的系统日志内容。
ugripper/ 下日志设备运行日志文件；实际数量取决于设备运行和日志留存状态。

下载异常时

页面提示设备忙，先等待占用操作结束。浏览器中断或网络断开后，检查下载列表中是否有失败/未完成文件，重新获取；不要把仅开始下载视为已经取得完整日志。

下载与录制互斥。获取日志期间不要开始录制或启动其他维护。诊断时不必先重启设备；先保存现场时间、提示和日志更利于定位原因。

建议交给支持人员的信息

设备 SN、Web 软件版本、问题时间、操作步骤、期望结果、实际提示、受影响的左右侧、episode 名称、完整日志包，以及能说明问题的界面图。

录制数据

10 · 浏览目录与整条下载

控件用途
路径文字当前目录相对于数据根目录的位置。进入目录后随导航变化。
打开进入某个目录，查看该目录下的文件或子目录。
打包下载把选中目录流式打包为 .tar 下载到电脑，适合一次获取完整 episode。
上一级返回父目录；用于逐层退回数据目录。
上一页 / 下一页目录项目较多时翻页；无前页或后页时对应按钮不可用。列表按名称倒序，较新的日期/编号通常靠前。

推荐下载方法

  2. 按目录层级找到目标设备的数据和 episode_日期_编号。
  3. 选择“打包下载”，在浏览器下载列表中观察进度。

录制数据 · 文件解释

11 · 单文件下载与数据完整性

常见内容用途
视频文件 .mkv主摄、触觉、双目等图像数据。播放器能否直接播放取决于编码支持；缺少 H.265 解码能力不等于文件损坏。
sensor / Fays .mcap编码器、IMU、双目等结构化时序数据，通常由数据工具读取，不按普通视频打开。
metadata.json本条录制的元信息与质量相关字段，用于数据检索、检查和后处理。
calibration.json该条数据使用的标定信息。不要仅下载视频而遗漏需要配套使用的标定。
ego/ 与音频在相应功能启用且成功产出时出现；具体内容由设备配置和录制流程决定。
stopwatch_timing.json时间同步测试额外写入的触发时间记录，见第 21 页。

操作与验证

在文件所在行点击“下载”即可获取单个文件；只排查某个小文件时比整条打包更方便。传输完成后核对浏览器状态和解包结果。网页下载成功只代表传输完成，不代表视频帧、时间戳或传感器数据全部合格。

传输中无法录制。单文件接口支持范围读取，但浏览器是否恢复由浏览器决定；目录打包流不能假定支持同样的断点续传。中断后应重新检查完整性。
升级维护 · 软件

12 · 查看版本与安装软件包

查看版本时注意

“未安装”表示未获取到该软件的安装版本。主摄 iSerial 是固件标识，不等同于夹爪 SN。夹爪版本由设备自动读取，可能显示等待自动读取、状态待更新或不可用；页面没有手动读版本按钮。

软件升级步骤

  1. 取得管理员提供的正确 .deb 软件包，核对目标设备与版本。
  2. 在“软件升级”选择文件，点击“上传并安装”。
  3. 检查确认弹窗中的文件名，输入维护密码并确认。
  4. 等待上传、安装和服务恢复；在“任务进度”查看结论。
  5. 如页面暂时失联，等待服务恢复后重新访问，再核对软件版本及设备状态。
允许的软件包说明
ugripper数采主程序与随包功能。
das-usb-updaterUSB 更新组件。
bluetooth-gatt-server蓝牙相关服务。
databot-device-joint设备配套服务。
device-ota-mender设备 OTA 组件。
按包内部名称校验白名单，支持 arm64/all，允许同版本覆盖安装。文件必须非空且小于 200 MiB；不会在线下载缺失依赖。
升级维护 · 固件

13 · 主摄与夹爪固件升级

选择类型文件与行为
主摄固件 · 左右一起升级选择一份 .img，系统按左右侧顺序处理。版本相同时默认跳过；确需重刷同版本才勾选对应复选框。
夹爪固件 · 左右一起升级选择一份 .hex，系统按固定左右夹爪串口顺序升级。主摄的“同版本重刷”选项不适用于夹爪。
  1. 确认两个目标设备均正确连接，停止录制、下载和其他维护。
  2. 先选择正确固件类型，再选对应文件；切换类型会清空此前文件选择。
  3. 点击“上传并升级”，核对文件名与“两侧升级”，输入维护密码并确认。
  4. 全程保持供电和 USB 连接，等待设备回读和任务完成。
  5. 分别核对左右结果；回到概览检查两侧识别情况，并进行适当抓图复查。
两侧升级不是原子事务。第一侧成功、第二侧失败时，已成功侧不会自动回滚。请保留逐侧结果和日志，由维护人员决定后续处理。

主摄完成后会检查版本与硬件身份；iSerial 可以随固件改变。上传完成不等于刷写成功。网页关闭后已提交的刷写仍可能继续。

升级维护 · 任务确认

14 · 任务进度和失败处理

阶段 / 情况含义与动作
正在上传 X%文件传到设备的进度；还没有证明软件安装或固件刷写完成。
已接收 / 正在执行后台维护已接受或正在操作。保持电源与设备连接，等待具体结论。
任务结束 / 100%界面完成状态展示；必须同时检查文字和逐项结果，失败任务也可能显示已结束的进度条。
连接中断网页无法更新，不代表后台操作取消。先恢复网络后重新查看任务，不立即再次升级。
单侧失败记录失败侧与已成功侧版本，保存日志。不要假设两侧都未改变。
设备或服务重启未完成维护任务可能被标记失败，不会自动重试烧录。重新确认状态后再决定是否重试。

常见拒绝原因

  • 维护密码错误：重新打开操作弹窗输入；本次请求未派发维护。
  • 设备忙：等待录制收尾、下载、读取会话或测试结束。
  • 文件过大/为空/类型不符：重新取得正确文件，不要通过改扩展名绕过。
  • 包不在白名单或依赖不满足：向维护人员取得适配设备的完整交付包。
  • 系统盘不足：联系管理员处理存储；不要删除不明系统文件。
每台设备只保留一份待提交上传。不要由多个人同时上传不同文件；任务结束后上传文件会清理。

配置 · 只读编码器

16 · 查看编码器当前位置

操作步骤

  1. 确认设备空闲，点击“开始读取”。无需维护密码。
  2. 查看左右原始计数、角度、弧度以及读取时间；需要时在符合设备操作规范的范围内改变姿态，观察数值变化。
  3. 查看下方目标/实测频率、剩余秒数和丢失计数，判断本次读取质量。
  4. 完成后点击“停止读取”，再进行正式录制或维护。
字段解释
原始计数无符号寄存器原值。大于等于 32768 的值换算角度时按有符号 16 位计数处理。
角度 / 弧度同一位置的两种单位。可出现负数；例如原始计数 61364 对应约 −22.92° / −0.4000 rad，不表示读数坏了。
100 Hz 目标 / 实测后台持续采样目标为 100 Hz；实际频率受设备和传输影响，浏览器画面刷新也受显示帧率限制。
丢失 / 读取时间帮助判断读取是否持续更新。停止后保留的是最后一次读数，不是当前实时值。
一次最多读取约 60 秒；主动停止、隐藏/离开页面或断连后释放串口。读取不写零位，但读取期间与录制、维护互斥。
配置 · 高风险标定操作

17 · 左右编码器独立标零

用途与前提

重新设定所选编码器的零位，改变该侧现有标定。仅由了解标定流程的人员，使用指定标零治具，在正确设备姿态下执行。读取显示值异常时，不应未经检查就直接标零。

  1. 确认所需标零的是左侧还是右侧，停止录制、读取会话和其他维护。
  2. 按设备标定流程安装指定治具并固定正确姿态。本文不替代机械治具装配说明。
  3. 点击对应“左编码器标零”或“右编码器标零”。
  4. 核对弹窗中的侧别，输入维护密码，勾选“我已安装指定标零治具，并确认设备姿态正确”，再点击“确认执行”。
  5. 等待任务结束，检查所选侧结果；完成后通过只读“编码器读数”复核，再按标定流程移除治具。
错误姿态下的标零会造成后续角度测量偏差。页面不提供撤销按钮；另一侧不会随本次单侧操作自动标零。
配置 · 时间同步测试

18 · 设置毫秒表测试任务

参数允许值与含义
每组录制时长整数 1–3600 秒，默认 100 秒。从发送录制 START 指令计时，硬件启动耗时可能使视频略短。
测试组数整数 1–100，默认 1。按顺序执行多组，任一组失败后不再继续后续组。
毫秒表延迟启动非负整数秒，默认 2，必须小于每组录制时长；同样从 START 指令计时。
  1. 按配套硬件规范连接 GPIO139 外接毫秒表，使需要比较的相机能够拍到适当显示区域。电气连接由具备相关能力的人员完成。
  2. 提前保存合适的编码和电源频率配置；确认数据盘空间和供电。
  3. 填写三项参数，点击“开始时间同步测试”。该入口会启动真实录制，不需要维护密码，也没有额外的密码确认弹窗。
  4. 任务期间不要使用实体录制按钮；在页面查看组数、阶段和剩余时间。
默认示例：100 秒、1 组、延迟 2 秒。每组前后还有各 5 秒清零及录制启动/收尾耗时，总耗时不只是输入的录制秒数。
配置 · 时间同步测试结果

19 · 看进度、停止与评估同步

清零 5 秒→START→延迟后走表→STOP→清零 / 收尾

停止和断线

点击“停止时间同步测试”后，等待当前录制和毫秒表完成收尾。关闭网页或拔掉网线不会停止后台任务；重新连接可看最新状态。维护服务重启会尝试复位毫秒表并停止该任务已知的录制，将任务标记为中断，不自动续跑。

状态如何理解
毫秒表清零中设备正在控制外接表复位，等待规定时间。
等待毫秒表启动START 已发出，正在等待设置的走表延迟。
录制中 / 收尾中正在获取数据，或等待文件完成与检查。不要在收尾前断电。
采集完成本任务录制与文件检查完成。尚不代表光学时间同步误差合格。
已取消 / 失败 / 中断不能作为完整通过的测试。查看失败组和日志，再确定是否重测。

下一步如何取证

从“录制数据”下载对应 episode。每组增加 stopwatch_timing.json，包含实际 GPIO 边界、START/STOP 时间。结合视频中毫秒表读数和相应标定流程另行评估同步误差。

管理员结果位置：/var/lib/ugripper-web/time-sync.json；time-sync-results/ 保留最近 20 次报告和日志。网页没有单独的“下载测试报告”按钮。

配置 · 生产压测

20 · 启动连续录制压测

测试组固定计划
A 组每轮录制 120 秒、停止间隔 20 秒，共 51 轮，名义 1 小时 59 分。
B 组每轮录制 300 秒、停止间隔 20 秒，共 11 轮，名义 58 分 40 秒。
合计共 62 轮，名义 2 小时 57 分 40 秒，实际还要增加启动、停止收尾等时间。

启动前检查

  • 相机、传感器、数据盘和需要联动的 Ego 已准备好；供电能维持整个测试。
  • 数据盘能保存大量正式 episode。该页面不提供自动估算空间或测试后清空数据。
  • 没有下载、编码器读取、升级、抓图或时间同步测试正在运行。
  1. 点击“启动生产压测”，阅读时长和持续运行提示。
  2. 点击“确认执行”。无需维护密码，但会开始真实、长时间录制。
  3. 观察当前组、组内轮次、阶段、剩余时间与失败计数。
  4. 需要中止时点击“取消压测”，确认后等待收尾。
关闭网页或拔掉网线后仍继续运行。不要把断开浏览器当作取消，也不要在任务期间操作实体录制按钮。
配置 · 生产压测判定

21 · 读取压测结果

怎样才算不通过

任一条件成立即不通过：A 组失败 ≥3 次，或 B 组失败 ≥2 次，或总失败 >3 次。触及门限后仍继续计划轮次，以保留完整证据；但无法安全停止当前录制时会中断整项任务。

失败计数示例判定解释
A=2，B=1未触及失败门限；还须完整跑完并以最终“通过”状态确认。
A=3，B=0A 组达到 3 次，判不通过。
A=0，B=2B 组达到 2 次，判不通过。
已取消 / 异常中断无论之前成功多少轮，都不作为完整通过。

每轮主要检查什么

正式质量结论、录制时长、必需文件和验证错误日志。时长允许目标 −2 至 +10 秒。每轮最多等待启动 30 秒、停止收尾 90 秒。展开“测试详情”可看轮次、实际时长、episode、失败原因与日志。

如何保存结果

记录任务最终状态、A/B 失败数和异常轮次，下载相关 episode 与设备日志。断网时页面进度不再更新，恢复连接后以设备后台状态为准。

管理员结果位置：/var/lib/ugripper-web/production.json；production-results/ 保留最近 20 次报告。正式 episode 留在数据盘，不因压测结束自动删除。

升级维护 · RK3588

24 · 3588 启动固件升级

用于升级背包 RK3588 的 boot 启动固件，流程与背包生产工具一致。只接受适配当前背包硬件的 FIT boot.img；不是整盘镜像、rootfs、Mender 包或主摄固件入口。

操作步骤

  1. 取得管理员提供的适配镜像，保持稳定供电。背包电量须至少 20%；低于 20%、电量不可用或读数超过 20 秒未更新时无法升级，充电中也不豁免。停止录制、测试、下载及其他维护。
  2. 在“3588 启动固件升级”中选择 .img 文件，点击“上传并升级 3588 固件”。文件必须非空且小于 200 MiB。
  3. 核对文件名和自动重启提示，输入维护密码，确认执行。密码由管理员另行通知。
  4. 等待镜像检查、分区写入和回读校验。开始写入前会再次检查电量；期间不能断电或拔插设备。
  5. 写后校验通过会自动重启，网页暂时断开。设备启动后重新访问，查看“3588 启动固件重启后校验通过”。
任务结果含义与处理
启动分区已匹配当前分区内容与镜像一致，跳过写入和重启。
等待设备重启已完成写后校验，尚未完成重启后校验；不能当作最终成功。
重启后校验通过新启动周期中分区回读 SHA-256 匹配；之后还应检查相机、传感器和正常录制功能。
校验失败 / 任务中断不会自动再次刷写。保留任务提示和日志，交由维护人员处理。
该流程没有 A/B 自动回滚。若错误镜像导致设备无法启动，需要离线恢复。内容哈希和 RK3588 类型校验不能替代板级硬件兼容确认，务必使用对应交付镜像。
