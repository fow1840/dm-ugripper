## NTP 操作示例（在测试设备执行）

1. 数据盘、左右相机/夹爪正常，设备处于待机；确认测试网络可访问 NTP 服务器。
2. 向前偏移并授时：

   ```bash
   sudo date --set='+120 seconds'
   sudo systemctl restart ugripper-ntp-sync.service
   journalctl -u ugripper-ntp-sync.service -n 80 --no-pager
   ```

3. 确认系统时间已恢复、双目 ready 后录制 30–60 秒，停录并深度校验；重复 5 组。
4. 待机时改用 `sudo date --set='-120 seconds'`，重新执行授时与录制步骤。
5. 没有外网时，人工正/负跳时只能验证时间映射恢复，不能记为 NTP 服务器授时通过。正常 NTP 服务在录制中应跳过授时；录制中人工跳时属于单独的故障注入用例，完成后待机恢复真实时间再继续测试。
6. 深度校验使用 `bash test/scripts/validate_episode_data.sh <episode目录>`；比较视频、Fays IMU 和 encoder 的首帧/尾部、单调性与 gap。双目精确时间使用 Fays MCAP camera publish_time，不能把双目 MKV 的名义 PTS 当作 Unix 时间真值。

## 部分蓝灯变长的 Ego App 原因

按本次现场反馈：UGripper 发送“停止录制”指令后，Ego App 在生成自己的 metadata 时，主动通过厂商 SDK 查询头带固件版本。查询失败会反复重试，本次观察额外耗时约 **11.4 秒**；这一阶段 UGripper 仍在等待 Ego App 完成收尾。

该耗时应结合 Ego App 日志定位到 metadata/固件版本查询阶段。11.4 秒是本次观察值，不是每次固定延迟；UGripper 的并行停录、交接与有界检查可以减少自身等待，但不能消除 App 内部的 SDK 查询重试。测试报告分别填写 App 查询阶段与 UGripper 补拉/校验/刷盘阶段耗时，保留 [STOP_DIAG]、ego_sync 状态、App 日志和失败 metadata。
