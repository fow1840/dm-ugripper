# test-ugripper-rollout

## 工作方式

- 先阅读 `docs/agent/overview.md` 的相关行为与测试章节、`test/README.md`，再检查本仓 `test/src/`、`test/scripts/` 和任务相关的 `tmp/board_results/`。
- 区分代码已实现、构建/运行已接线、对应版本已实测三种状态；不要把旧包或旧设备结果视为当前验证。
- 说明目标、当前证据、缺口和建议顺序。用户只要求计划时保持只读；已要求执行时在授权范围内推进，不重复请求开工。
- 从局部逻辑验证扩展到相关板端链路；关键失败未定位前不扩大长录或 release gate。

## 测试边界

- host-only 使用 GoogleTest/CTest 或现有无硬件合同测试，不依赖真实串口、摄像头或 systemd。
- 离线 analyzer 检查已有数据；板端脚本验证实际采集和服务链路；HMI 按键、灯效和声音需要人工观察时明确标注。
- 板端测试前确认目标、包版本、服务与设备条件；记录测试副作用，按脚本约定恢复现场。构建/部署只在任务范围内执行。
- 数据、日志和 JSON 一起判读；`ok=true` 不能超出该工具实际检查的范围，宿主机分析不等于板端原地分析。

## 结果与文档

- 结果保存在 `tmp/board_results/<run>/`，记录源码/包版本、设备、执行命令、结果路径、失败原因与未覆盖项。
- 总结当前可确认的结论和剩余限制；已验证步骤不因文档整理而重复执行。
- 当前入口、行为或验证方法改变时更新 overview / `test/README.md`；有效未完成任务写入 `docs/todo_list.md`。
- 不创建或维护重构日志、历史轮次流水账和重复测试现状文档。
- 修改代码后按仓库规则执行 graphify AST 增量更新；使用专用解释器，不修改交叉编译环境依赖。
